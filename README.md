# Sizzle — LAN restaurant ordering platform

A React + Node.js app for restaurants. One PC runs the server; tablets and other computers on the same network open it in a browser. Customers browse a 3D menu and order, waiters manage tables and orders, admins manage the menu and promotions. Everything works **without internet**.

## Run it (server PC)

Requires **Node.js 22.13 or newer** (uses the built-in SQLite).

```bash
npm install
npm run build      # builds the web app into dist/
npm start          # starts the server on port 3000
```

On Windows you can double-click `start-server.bat` instead (it installs and builds on first run).

The console prints the address for the tablets, e.g. `http://192.168.1.20:3000`. Open it on each tablet/computer on the same Wi-Fi/LAN. Use a different port with `PORT=3001 npm start`. If Windows Firewall asks, allow Node.js on private networks.

Data (database + uploaded images) lives in `data/`. Back it up by copying that folder.

## Features

- **Client**: 39 meals in 11 categories (Fast Food → Burgers / Hot Dogs / Wraps, Sushi, Traditional, Kids, Steak, Dessert, Drinks → Hot / Cold / Coffee), a virtual **Promo meals** category (*Aksiyadagi ovqatlar*), event banners, search, live 3D models you can rotate and pull apart ingredient by ingredient, English / Uzbek.
- **HD mode**: the ✦ HD button in the 3D viewer switches to a **high-detail model** for every dish (cards show a `3D · HD` badge). 33 dishes are built in Blender as separate ingredient parts on real serving ware (paxta-pattern lyagan, kosa and piala, slate, glass, porcelain), so every ingredient lifts off the plate in "Separate ingredients" and is highlighted from the recipe list. The burgers use a real scanned bun; the Strawberry Chocolate Cake, Carrot Cake, Butter Croissant and Fresh Fruit Platter are photoreal Poly Haven scans (the cakes and croissant are single solid scans, so they can't be pulled apart). HD is remembered per device and falls back to Standard automatically if the device is too slow. See `web/public/models/CREDITS.md`.
- **Waiter**: live tables board (free / busy / bill), take orders for any table, add items to an open order, change order status (new → preparing → ready → served, or cancel with a reason), sound + toast alerts for new and ready orders.
- **Admin**: everything above plus **Events** (percent off, fixed amount off, *buy X get Y free*; per meal or category; weekdays, daily time window, date range; banner image upload), menu / category CRUD with photos and a 3D ingredient editor, staff and PIN management, table count. Seeded events: **Buy One Get One** (hot dogs), **Happy Hour** (drinks, 15:00–17:00, −20%), **Happy Friday** (fast food + dessert, Fridays, −15%).
- Discounts are calculated on the server when the order is placed, so tablets cannot tamper with prices. When several events apply to one item, the single best discount wins (they never stack).

## Rebuilding the HD models (Blender)

All HD dishes are generated by scripts in `tools/blender/` (Blender 4.2+; tested with 5.1). Each ingredient is a separate GLB node named with the meal's ingredient id (plus one static `base` node for the plate / glass / board); materials are procedural or painted, baked to textures for glTF.

```bash
# burgers (scanned bun + modelled ingredients)
blender -b --factory-startup --python tools/blender/build_burger.py -- --meal all --out web/public/models/hd
# every other dish; --meal also takes one meal id or a family: fastfood, sushi, traditional, kids, steak, dessert, drinks
blender -b --factory-startup --python tools/blender/build_dish.py -- --meal all --out web/public/models/hd
# add  --preview <folder>  to also render assembled + exploded look-dev images
```

`npm test` checks every GLB against the menu (each exploding part is one of the meal's ingredients and vice versa).

## Development

```bash
npm run dev        # server on :3000 + Vite dev server on :5173 (proxies /api and /ws)
npm test           # pricing engine, server API + permissions, i18n coverage
npm run typecheck
```

Layout: `server/` (Express + WebSocket + SQLite), `web/` (React + Vite + three.js), `shared/` (types, pricing/events engine, seed data used by both), `legacy/index.html` (the original single-file prototype).

## Security note

PINs are hashed on the server and sessions expire after 12 hours, with a lockout after repeated wrong PINs. This is designed for a trusted restaurant LAN, not for exposure to the internet — do not port-forward it.
